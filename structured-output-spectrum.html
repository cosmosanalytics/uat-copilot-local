The Structured-Output Spectrum

Seven ways to get structured output from an LLM, weak → strong, demonstrated live with a single WebLLM model running in your browser via WebGPU.

What's genuinely native here vs. built on top: Levels 2, 6, and 7 use WebLLM's own response_format parameter (json_object with a schema, and grammar with a hand-written GBNF grammar) — this is real, verified grammar-constrained decoding backed by XGrammar under the hood (the same engine named at level 7 of the source spectrum), confirmed against WebLLM's own official examples and MLC's engineering blog. Levels 1, 3, 4, and 5 use ordinary unconstrained generation with application-level logic layered on top — a system prompt asking for JSON (L1), a prompted function-call convention rather than WebLLM's separate, less-documented native tool-calling API (L3, kept consistent with the fenced-block convention used across this portfolio's other apps), a validate-and-retry loop with the LLM (L4), and a deterministic client-side coercion/typed-failure layer with no LLM retry at all (L5). Illustrative: the worked example (extracting a task from a sentence) is a toy schema chosen for clarity, not a production form.

Bonus: chained handoff

The source spectrum's closing point: structuring isn't a one-time gate. In a chained agent, the output of one LLM-to-tool handoff becomes the input to the next — and needs the same constraint applied again, not assumed to still hold.
