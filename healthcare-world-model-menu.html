Healthcare Process Studio — Menu Edition

10 tool calls — one per stage of a single patient's standard US insurance-based care journey (Registration → Eligibility → Prior Authorization → Clinical Encounter → Medical Coding → Claim Submission → Adjudication → Payment Posting → Denial Management & Appeals → Patient Billing). Each tool is a pure, deterministic function modeling the real math and gating rules of that stage (deductible/coinsurance/copay math, CPT/ICD-10 coding, prior-auth clinical criteria, denial/appeal outcomes). This edition has no model in the loop at all — instead of an LLM deciding which tool to call, you pick the action yourself from a plain menu below. Run stages manually to study the logic, or use the menu to run the whole case in one click. Stage order and definitions are adapted from published revenue-cycle-management and utilization-management literature (see footer for sources) and simplified for illustration — this is not medical, billing, or legal guidance.

Patient & insurance
Benefit design (annual, year-to-date)
Planned service & prior authorization
Preauth is only required for imaging_advanced / surgery / inpatient_admission (a simplified prospective-utilization-review rule). office_visit_established never requires it.
Claim adjudication
The contracted "allowed amount" is what the payer recognizes as payable at all; the difference from the billed charge is a contractual write-off the provider absorbs — not paid by the patient. Set this to 0 to force a denial and exercise the appeals path.
Denial management — appeal
Only used if Adjudication results in a denial. Strength ≥ 0.6 overturns the denial on appeal (simplified); below that, the denial is upheld and the claim closes as a provider write-off with no plan or patient payment.

Case state

Live values as each stage completes. Denials, write-offs, and negative or blocked outcomes are flagged — worth tracing back to see which upstream input caused them.

Tool call log

Every execution — manual or agent-driven — with its result, so you can audit exactly what ran.

Menu orchestrator

Pick an action from the menu and click Execute — this calls the exact same stage functions shown above, directly, with no model deciding anything. It's the same job an LLM tool-calling orchestrator would do (choosing which tool to call next), just done by you from a plain menu instead of by typing a request to a model.
Runs entirely as static client-side JavaScript — no server calls, no model, nothing leaves your browser. Stage sequence adapted from published revenue-cycle-management and utilization-management process descriptions (TruBridge's 12 Steps of RCM, AMS Solutions' 8 Stages of the Medical Claims Lifecycle, and the Wikipedia summary of Utilization Management's prospective / concurrent / retrospective review phases), simplified into a single illustrative 10-stage pipeline. Not a representation of any specific payer's actual rules.
