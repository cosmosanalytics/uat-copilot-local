Cognitive Loops × Epistemic Safety

“How much of the knowledge boundary actually gets checked, at each tier of thinking?”
Key Law
Fact-checking strictly increases with the level of thinking: Verification escalates from zero checks in Reflex, to single-pass grounding in Deliberation, to calibrated self-critique in Metacognition, to continuous nested verification at every step in Planning.

Goal: Epistemic safety isn't a single on/off switch. It's a dial that tightens as the cognitive loop escalates — Reflex spends none of the safety budget; Planning spends all of it, repeatedly, because it's the tier most likely to drift from its own starting assumptions.
Analogy: A reactor's safety instrumentation doesn't check the same way during idle standby as it does during a reactivity transient. The same sensors exist at every tier; how often and how strictly they're read is what actually changes.
• Formal Decision Gating Function
Tri-state epistemic gate calibrated to task risk:
Action = Answer  if [C ≥ τstakes ∧ Contradiction = 0]
Action = Hedge   if [τlow ≤ C < τstakes]
Action = Abstain if [Contradiction > 0 ∨ Coverage < τcov]
• Production Safeguards & Anti-Drift
1. Deterministic Triage: Pre-route queries with static policy checks to prevent adversarial bypass of Reflex.
2. Asymmetric Budgeting: Early-exit subgoals when initial entailment is unambiguous to cap O(K × N) compute.
3. Anti-Sycophancy: Anchor contradiction tests in deterministic schemas/APIs, not ungrounded self-critique.
Best for: Deciding, before deployment, which tier a given request category is even allowed to run at — and refusing to let a Reflex-tier answer ship on a Stakes-Adjusted Risk that was never actually checked.
• The Cognition-Allocation loop decides how much Knowledge-Boundary checking runs — the two loops are coupled, not independent.
