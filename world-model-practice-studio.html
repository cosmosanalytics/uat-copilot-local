World Model Practice Studio

A small local LLM orchestrates 11 tool calls — one per stage of the World Model state-space chain (Aggregate → Forecast → Consensus → Disaggregate → Forecast Consumption → Dependent Demand → Firming → Capacity Pooling → Inventory → Monitor → Owner). Each tool is a pure, deterministic function; the model's only job is deciding which to call, in what order. Run stages manually to study the math, or let the agent orchestrate the whole chain.

World Model

Every engine is this same 11-stage chain, grouped here into four intuitive beats. Each tab holds that beat's editable inputs plus its stage cards — edit a field, click "Apply inputs & reset state" (it always resets the full chain, since a change anywhere downstream invalidates everything after it), then run stages manually to study the math, or use the AI Orchestrator below to run the chain via tool calls.
Historical demand (A) — comma-separated, 8 periods each
Aggregation is fixed for this example: Group 1 = WidgetA-East + WidgetA-West, Group 2 = WidgetB-East. Note the period-8 spike in WidgetA-East — it's a deliberately injected outlier.
Forecast — outlier bounds
At k=3 with only 8 points, a single extreme value inflates its own SD estimate enough that it often escapes clipping (the classic "masking effect"). Try k=1 or 1.5 and re-run Forecast to watch it get clipped instead — and watch the downstream Capacity alert disappear.
