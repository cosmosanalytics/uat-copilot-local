How AI Agents Work & Remember [Simplified]

The Operating System (The Active Doer) vs. The Memory Notebooks (The Knower)

🤖🎒📖
1 The Big Picture: An Agent is Two Different Things

⚙️ 1. The Agent Core OS (The "Doer")

The active robot worker. It listens to student requests, decides which notes to open, checks safety rules, and controls physical tools like smart lockers.

  • Listens: Receives prompts from students or campus sensors.
  • Guards: Stops unauthorized actions (e.g. keeps lockers locked).
  • Executes: Sends messages, triggers APIs, and asks teachers for approval.

🎒 2. The Memory Documents (The "Knower")

The external notebooks in its backpack. Foundation LLM models have instant amnesia after each answer. Memory documents let the agent remember across time and collaborate with others.

  • Persistent: Never forgets rules, student rosters, or past checkouts.
  • Accurate: Zero hallucinations because facts are looked up directly.
  • Shared: Multiple robots and teacher bots read the exact same pages.
2 The 4 Memory Notebooks in the Robot's Backpack
📘 The Playbook
`SKILL.md` (Procedural)
The step-by-step how-to recipe book. Tells the robot what order to do things in.
Recipe: 1. Check ID → 2. Verify eligibility → 3. Request waiver if needed → 4. Open locker.
📗 The Rulebook
Vector DB (Semantic)
The school policy manual. Indexed by meaning so the robot finds exact paragraphs fast.
Rule §4.2: "Robotics Kits require Grade 9+ or written faculty sponsor waiver."
📙 The Yearbook
Knowledge Graph (Relational)
Who is who, what is what, and where things are right now. Crisp, connected facts.
Fact Web: Tim is in Grade 7. Mr. Davis is his advisor. Kit #4 is in Locker B-12.
📓 The Whiteboard
Shared State (IPC)
The shared message board where peer robots and teachers talk to each other live.
Live Note: "Waiver pending for Tim on Kit #4. Approved by Mr. Davis at 2:05 PM."
3 A Concrete Story: How They Work Together in 4 Steps
Scenario: 7th-grade student Tim walks up to the Library Robot and asks: "Can I borrow Robotics Kit #4?"
Step 1 👂 Ingest Request
Agent Core hears Tim's question and automatically opens borrow_kit.md from its Playbook.
OS: "Running checkout protocol!"
Step 2 🔍 Read Notebooks
Core checks the Yearbook (Tim is Grade 7) and the Rulebook (§4.2: Grade 7 needs a teacher waiver).
Status: Ineligible without waiver!
Step 3 ✍️ Write & Notify
Core leaves Locker B-12 safely locked, posts a waiver ticket to the Whiteboard, and pings Mr. Davis's bot.
A2A Message: Sent to Mr. Davis
Step 4 🔓 Act & Update
Mr. Davis clicks "Approve". Core sees the update, clicks open Locker B-12, and updates the Yearbook: Kit #4 on loan.
Success: Locker B-12 Unlocked!
4 The 3 Key Takeaways: Why Separate the OS from Memory?

🧠 1. Eliminates Amnesia

AI models have no memory between queries. Storing memory in external documents ensures yesterday's approvals and locker checkouts are never lost.

🛡️ 2. Guarantees Safety

The AI model can suggest anything, but only the Agent Core OS has keys to open doors or charge cards. It enforces rules before taking real-world action.

🤝 3. Enables Teamwork

Because memory lives in shared documents rather than inside a single bot's head, the Library Robot, Teacher Bot, and Inventory Bot all stay in perfect sync.
