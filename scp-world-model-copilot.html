Supply Chain Planning Copilot — the World Model

One coherent demo across four enterprise AI guardrails, all grounded in a single real, deterministic 11-stage planning engine (Aggregate → Forecast → Consensus → Disaggregate → Forecast Consumption → Dependent Demand → Firming → Capacity Pooling → Inventory → Monitor → Owner). The engine has no decision variables of its own — it's a fully-observed state-space model that deterministically computes the consequence of any candidate decision. The AI copilot sits on top of it, never replacing its math.

What's real vs. illustrative: the forecast sub-pipeline (data cleaning, ADI/CV² segmentation against the real Syntetos-Boylan thresholds, Naive/SES/Croston model fitting, backtest-WMAPE selection) and every downstream stage are genuinely computed in this page — not scripted. There are two genuinely independent tool servers: a World Model server (5 tools) and a separate UAT server (4 tools) with its own schema set and its own handler function — the copilot's dispatch step routes each tool_call to whichever server owns that tool name, rather than everything living behind one handler. The tool schema + circuit breaker run on both servers with domain-specific rules each (a runaway-forecast-override check on the World Model side; an all-tests-must-pass check before UAT sign-off on the other). Every proposed plan change automatically gets a UAT test suite generated for it and can't be approved in the Review tab until it's signed off — you can drive that whole checklist manually with no model loaded. The XML-tagged prompt isolation, the SHA-256 hash-chained audit log, and the model-routing cost math are all real, working mechanics too. What's illustrative: $/M-token prices are modeled on published per-tier API pricing for small/fast vs. large/capable hosted models, applied to local models for intuition, not real billing; assistant-turn pre-fill (opening the model's own turn for it, mid-sentence) was attempted here and dropped — WebLLM's chat.completions.create() validates message roles and rejects a request whose last message is "assistant" outright, so there's no engine to be best-effort against; the reasoning scratchpad below is instead followed by an ordinary bridging user turn, and schema validation is what actually backstops the tool call regardless; the UAT test-case descriptions are auto-generated templates, not real test scripts from a production system; and the copilot itself approximates extended step-by-step reasoning with two-stage prompting (a separate capped "thinking" call before the final answer) rather than a model's native reasoning feature.
