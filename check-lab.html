Check Lab: build the checking for an agent product

A small order-desk agent has a store of records, a harness that builds its prompt, and a real-world ledger. This page is the checking infrastructure around it. Pick the risk tier from three questions, run the 12 checks from the cheat sheet (real world, stores, harness, answers), test the limits and people controls, and see an "is it enough" scorecard against the tier. Fix the store and the harness, run again, and watch the checks go green. Export a report and compare it after the model or prompt changes.

  1. The product: An order-desk agent with a messy store, a retrieval harness, a memory write gate and an action executor with caps, escalation, a kill switch and an audit log.
  2. The tier: Three questions give low, medium or high, and the tier decides which checks and controls are required.
  3. The 12 checks: Real-world probe, seeded world, human audit, stale or clash, find it again, plant bad facts, prompt peek, with and without, swap a fact, quiz it, show sources and ask a stranger.
  4. The scorecard: The four "it is enough when" tests, with an error interval and the number of clean cases still needed.
  5. After launch: Export a report, load an older one, and see what changed.

Honest label: this checks a small made-up product, so the numbers show how the checks work, not how your product behaves. The tier rule and the required checks are my own guidance, not a standard. The reference agent is plain code that can be fooled by stale and injected records on purpose, and it shares its logic with its own checker, which is exactly the blind spot the page measures. A small on-device model will be noisier, and each question is only one case. Checking never proves safety. It catches the failures you thought of. Nothing leaves your device.
