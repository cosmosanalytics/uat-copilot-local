Core Paradigm
Start with MPC
Plan several steps ahead, apply only the first, then look again.
The Receding Horizon Principle

1. Predict with a model: Forecast state trajectories over horizon H (t, t+1, t+2...).

2. Choose the best plan: Evaluate candidate controls against cost & constraints.

3. Apply only the first step: Execute control u(t) now.

4. Re-measure, repeat: Observe new state at t+1, shift window, re-solve.

"Step 1 needs a model. No model, no MPC. So we build the models first."

Why Receding Horizon Matters in AI
  • Robust to disturbances: Real-world tool calls fail, LLMs drift, and user intent shifts mid-session.
  • Feedback corrects drift: Never execute open-loop multi-step reasoning without re-checking intermediate states.
  • Hard constraint satisfaction: Enforces strict accuracy bars (≥95%), latency deadlines, and token budgets at every transition.

The State Equations

Pipeline stock = earlier pipeline + new order - arrivals

On hand = earlier on hand + arrivals - demand

Inventory position = on hand + pipeline stock

The MPC Feedback Loop:
Every period, the controller reads current on-hand inventory and pipeline stock, re-solves how much to order across horizon H, and applies only the first step.

Nine-Stage Observed World Model
  • 1. Forecast: Moving average of historical actuals.
  • 2. Consensus: Forecast plus human planner adjustments.
  • 3. Consumption: Subtract unfilled client orders.
  • 4. Dependent demand: Explode assemblies into components.
  • 5. Firming: Order to cover gap (MPC optimizes this step).
  • 6. Capacity: Check machine and supplier constraints.
  • 7. Inventory: Enforce component safety stock.
  • 8. Monitor: Flag safety breaches.
  • 9. Control: Route actions to component owners.

Knowledge Uncertainty
Model 2: The Centaur (AI Plus Human)
Versus Model 1: same input driver, but AI introduces epistemic knowledge uncertainty.
The AI Pipeline (Scale & Speed)

System 1: Fast, single-pass forward propagation through Encoding → Syntactic → Semantic → Reasoning → Decoding.

System 2: Deliberative iteration loop around the Reasoning pass.

The Four Knowledge-Boundary Checkpoints:

  • 1. Coverage: Did the agent touch all requisite facts?
  • 2. Contradiction: Clashes between generated output and source?
  • 3. Confidence: Calibrated token log-probabilities.
  • 4. Stack-Adjusted Risk: Potential cost of error × uncertainty.
The Human Metacognitive Loop

Monitor: Aggregates boundary scores into a composite trustworthiness metric.

Control Actions:

  • STOP: Final output accepted into production workflow.
  • RE-PLAN / RETRY: Loop back into reasoning with constrained prompts and search bounds.
  • ESCALATE: Route to human reviewer when risk bounds are crossed.

Human owns judgment, structure, and enterprise accountability.

Multi-Agent Thesis
One Working Memory, or Several?
An agent is a model plus its working memory: the context it reads and writes.
One Agent: One Working Memory

Thinking harder means writing more into the exact same context space.

  • Single context: Goal + Data + Reasoning Step 1 + Step 2...
  • Self-confirmation trap: The LLM reads its own previous reasoning back into attention and anchors on early mistakes.
  • Zero concurrency: Complex sub-tasks must wait in a sequential queue.
  • Context saturation: Memory bloat causes earlier constraints to be forgotten.
Several Agents: Several Working Memories

One shared foundation model, but disjoint working memories.

  • Agent 1 (Planner): Decomposes goal; stores high-level roadmap.
  • Agent 2 (Worker): Receives part A; implements solution in fresh context.
  • Agent 3 (Checker): Receives ONLY the output + validation rules.
  • Independent perspectives: Eliminates correlated reasoning bias.
The AI Factory Slide 11 / 17
Parallelism & Verification
Several Working Memories Make Two Things Possible
The price: working memory must be filled; instructions are copied; total tokens are not lower.
1. Parallel Processing

Each working memory executes simultaneously.

  • One memory: Task 1 → Task 2 → Task 3 runs in series.
  • Three memories: Task 1, 2, and 3 run concurrently, followed by a merge step.
  • Critical path latency: End-to-end finish time is determined by the thickest (longest) parallel branch, not the sum of parts.
2. Cross Validation (Blind Audit)

A second working memory verifies without anchoring.

  • Worker memory: Intermediate reasoning + final artifact.
  • Checker memory: Receives ONLY the final artifact + ground truth rules. The worker's reasoning stays behind!
  • Zero confirmation bias: The checker starts clean and cannot inherit the worker's flawed intermediate steps.

Dynamic Dilemma
Static Team versus Dynamic Team
A fixed team wastes compute on easy requests and breaks on hard ones.
The Static Multi-Agent Traps
  • Over-engineering simple cases: Running 4 agents and 4 working memories for a simple address update costs 4× tokens and adds 3 hops of latency for zero gain.
  • Rigidity on hard edge cases: When a specialist hits unexpected ambiguity, a static DAG cannot dynamically spawn a rival critic or adjust audit depth.
  • Context decay across hops: "Every extra hop blurs the goal." Forcing all requests through a fixed pipeline accumulates unnecessary semantic noise.
The Dynamic Solution
  • Adjust topology per request: Simple requests get one fast agent (reflex). Ambiguous or high-risk requests get parallel workers and an adversarial critic.
  • Adjust topology mid-flight: If step 1 returns high confidence, skip downstream checkers and approve. If step 1 reveals high contradiction, dynamically inject an auditor.
  • The Core Thesis: The team topology is not a static org chart. It is an operational decision variable.
A good team is not more agents. It is the minimum topology that provably guarantees the safety rule.
The AI Factory Slide 14 / 17
Rolling Horizon Control
MPC for Dynamic Team Design Optimization
Treat the team topology and verification depth as the control variable u(t).
The MPC Formulation

State x(t):

  • Goal progress & residual epistemic uncertainty.
  • Working memory load per active agent node.
  • Cumulative token expenditure & elapsed critical-path latency.

Control u(t) (Action Space):

  • Topology: Spawn, prune, or bypass agent nodes.
  • Edge Routing: Raw trace vs. evidence vs. verdict only.
  • Verification Depth: Dynamic audit sampling rate p_audit.
  • Model Tier: Edge model (Bespoke Nimble) vs. frontier model.
The Receding Horizon Optimization Loop

1. Predict over Horizon H: Simulate candidate team topologies (Single agent, Parallel workers, Adversarial debate).

2. Optimize: Drop candidate topologies that violate safety bars. Select cheapest feasible team structure.

3. Act & Observe: Execute step t with the chosen team. Measure tool output and consensus variance.

4. Shift & Re-plan: Advance horizon to t+1. If unexpected contradiction is measured, dynamically inject an opposing Critic for the next step.

Theoretical Synthesis
Structure, Incentives, and Control
Graph theory sets structure. Game theory sets incentives. MPC steers them dynamically.
1. Graph Theory

Structure: Who talks to whom

  • Nodes: Agents with isolated working memories.
  • Edges: Information conduits passing evidence, never reasoning.
  • Critical path: Sets finish time.
  • Dynamic pruning: Removes unnecessary hops to prevent goal blur.
2. Game Theory

Incentives: What drives agents

  • Opposing goals: Creator wants acceptance; Critic is rewarded for hunting flaws.
  • Random audit: Stochastic inspection prevents the creator from predicting what gets checked.
  • Independent voters: Clones produce correlated bias; distinct working memories produce truth.
3. Model Predictive Control

Steering: When to deploy what

  • Graph and Game theory define the admissible space of team configurations.
  • MPC chooses the optimal configuration dynamically over time.
  • Low uncertainty → Minimal linear graph, 0% audit.
  • High uncertainty → Adversarial debate, 100% audit, or human escalation.
