Client-side reasoning demo · WebLLM + WebGPU, no backend

Extended Thinking, Under the Hood

Give a local model an explicit reasoning budget before it has to answer, and watch what changes. Run the same prompt with no thinking budget next to a chosen budget, side by side, using a model running entirely in your browser via WebGPU. Below that: the same "knowledge boundary" idea applied to tool calls — a strict schema boundary and a deterministic circuit breaker, catching bad model output before it can act.

What's simulated vs. real: the reasoning-budget section above does not use Anthropic's actual Extended Thinking feature (a distinct model capability, invoked with a thinking: {budget_tokens: ...} parameter on the Claude API, producing genuine interleaved reasoning) — it approximates the idea with plain two-stage prompting against a small open-source model. The guardrails section below is different: schema validation and the domain-rule circuit breaker are ordinary integration code, not model-specific, so that part is a real, working implementation of the pattern — it would work the same in front of Claude, Llama, or anything else.

Guardrails · schema boundary + circuit breaker Idle

Same knowledge-boundary idea, applied to a tool call instead of a text answer. The model proposes a warehouse transfer as JSON; a strict schema check rejects malformed calls before anything runs; a deterministic domain check (mass balance — can't ship more than is on hand) blocks a well-formed but invalid call. Unlike the reasoning demo above, this part is a real, honest implementation of the pattern — schema validation and business-rule checks are ordinary integration code, not something that only works with a specific model or API.

Uses the thinking budget set above (currently applies here too), so the model reasons about the request before emitting the JSON call.

Load a model above, then propose a transfer to see it checked against the schema and the domain rule before (maybe) executing.
Demo only. Model quality varies a lot at this scale (small models run fully client-side so the demo works with zero backend and zero API cost) — the point isn't that the model gets every problem right, it's seeing how the reasoning trace changes the final answer when it's allowed to work through the problem first versus forced to answer immediately, and how schema + domain checks catch bad tool calls regardless of what the model outputs. Runs entirely in your browser via WebLLM / WebGPU — nothing is sent to a server.
