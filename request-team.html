Business requests: one agent or a team?

A batch of customer requests is handled two ways. One agent does everything in a single working memory. Or a team does it with several working memories, each holding only what its job needs. Compare the results, what each agent saw, and what the checker caught.

  1. Sorter agent: Reads only the request and decides what kind it is.
  2. Specialist agents: An order-status agent and a refund agent. Each has only its own tools and rules, and its own working memory.
  3. Checker agent: Starts fresh. It sees the request, the answer and the facts the tools returned, not the specialist's reasoning, and checks them against the rules.
  4. Controller: Policy in code. Large refunds wait for a person.
  5. You: Choose one agent or the team, how many requests run at once, and whether to inject a slip to see who catches it.

Honest label: the orders, requests and policy are made up, and the batch is tiny, so the results are anecdotes, not measurements. Small models make mistakes, and the scripted agents never do, so use the language model to see real slips. The injected slip is a demonstration: it replaces an agent's answer with a refund claim that no tool made. The model is one on-device model on one GPU in one tab, so parallel runs may queue. Times are measured in your browser, and the scripted agents use timers. Nothing leaves your device.
