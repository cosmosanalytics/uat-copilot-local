Knowledge Graph & Boundary Guardrails

A knowledge graph of the full 11-stage supply-chain planning process (Aggregate → Forecast → Consensus → Disaggregate → Forecast Consumption → Dependent Demand → Firming → Capacity Pooling → Inventory → Monitor → Owner), auto-generated from the same data structures the engine actually runs on — plus a live checker that tells you, for any answer the copilot gives, exactly which parts are grounded in a real tool call this turn, which are unverified claims about something real but not fetched this turn, and which reference something that doesn't exist at all.

What's real vs. illustrative: the graph's nodes and edges are generated programmatically from the live WORLD config and the tool schemas below — not hand-drawn, so it can't drift from what the engine actually computes. The entity-grounding check is a real, working guardrail: it regex-scans the model's final free-text answer for entity-shaped ids (SKU-, COMP-, RES-, DC-), cross-checks each against the real known set, and flags anything the model asserted that no tool call this turn actually verified. This is a genuinely different guardrail from tool-argument schema validation — schema checks catch a malformed request before it runs; this catches an ungrounded claim in the model's free text, which schema validation has no visibility into at all. What's illustrative: the underlying forecast numbers reuse the same small synthetic 3-SKU world as the companion app, and "unverified" is a heuristic (a true fact the model recalled correctly from earlier context would also get flagged) — it's a boundary-awareness signal, not a full fact-checker.
