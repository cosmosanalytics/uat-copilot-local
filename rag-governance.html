iWhat this demonstrates

A small language model runs entirely in your browser (WebLLM, no server, no API key). Instead of trusting the model's memory, every answer is grounded in specific document chunks retrieved from a library you control — and every chunk in that library went through the same quality-check → ownership → approval → audit-log pipeline as the data quality console. So when the model answers, you can see exactly which chunks it used, who approved them, and whether those chunks had any known quality issues at the time. That's the traceability link: model output → specific governed data.

1Document library

Add source documents (paste text, or load the sample library). Each is split into chunks, and each chunk is checked for quality issues before it can be approved for retrieval.

2Chunk quality & approval queue

Automatic checks per chunk: near-duplicate content, contradiction with another approved chunk, too-short/empty text, missing source metadata, and staleness (if a date was given). A chunk only becomes eligible for retrieval once it is Approved by someone — and approval nudges you to name a different person than whoever added it, same review discipline as the rules workflow in the data quality console.

3Model & retrieval settings

Pick a local model to generate answers, and how chunks are found. Both retrieval methods run on-device — nothing is sent anywhere to search.

4Ask a question

The model will only see the retrieved chunks below plus your question — it is instructed not to use outside knowledge, so you can judge the answer against the exact sources shown.

5Audit log

Every document add, chunk status change, approval, and question asked — who did it, when, and (for questions) exactly which chunks were used.

Runs fully client-side: WebLLM (@mlc-ai/web-llm) loads a small open model via WebGPU for generation; if you pick semantic retrieval, Transformers.js (@huggingface/transformers) loads a small embedding model (Xenova/all-MiniLM-L6-v2) via WASM on CPU. The document library and audit log persist in this browser's local storage. Nothing is uploaded anywhere.
